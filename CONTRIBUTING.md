# Contributing

Спасибо за желание улучшить Awesome AI Skills.

Этот репозиторий — курируемый список, а не автоматический каталог всех найденных проектов. Главная цель — собирать skills, которые решают реальные задачи, понятны пользователю и достаточно безопасны для осознанной установки.

## Что можно добавить

Подходят:

- отдельные Agent Skills;
- коллекции skills с понятной структурой;
- официальные каталоги и примеры;
- установщики и инструменты управления skills;
- документация и спецификации, важные для экосистемы.

Проект должен:

1. Быть публично доступен.
2. Содержать настоящий `SKILL.md` или явно работать с форматом Agent Skills.
3. Иметь понятное описание и инструкции по установке или использованию.
4. Иметь лицензию или явно указанные условия использования.
5. Решать конкретную практическую задачу.
6. Не содержать очевидно опасного, скрытого или вводящего в заблуждение поведения.

## Что обычно не добавляется

- обычные prompt-коллекции без формата Agent Skills;
- заброшенные проекты с неработающей установкой;
- точные копии и forks без значимых отличий;
- SEO-спам и каталоги, созданные только для продвижения;
- репозитории без документации или понятного назначения;
- инструменты для AI-агентов, не связанные со skills;
- проекты, которые требуют запуска непрозрачных скриптов без объяснения их работы.

## Формат записи

Добавьте проект в подходящую таблицу в `README.md`:

```md
| [owner/repository](https://github.com/owner/repository) | Одно конкретное предложение о том, какую задачу решает проект. |
```

Хорошее описание:

```md
| [example/angular-review-skill](https://github.com/example/angular-review-skill) | Проверяет Angular-код на ошибки, архитектурные проблемы, accessibility, производительность и регрессии. |
```

Слабое описание:

```md
| [example/angular-review-skill](https://github.com/example/angular-review-skill) | Очень полезный и мощный skill для разработчиков. |
```

Не добавляйте текущее количество GitHub Stars в описание: оно быстро устаревает. Популярность можно указать в Pull Request как один из аргументов.

## Как открыть Pull Request

1. Создайте fork репозитория или отдельную ветку.
2. Добавьте проект только в одну наиболее подходящую категорию.
3. Проверьте ссылку, README, `SKILL.md`, лицензию и способ установки.
4. Убедитесь, что такой проект еще не добавлен.
5. Откройте Pull Request с коротким названием: `Add owner/repository`.

В описании Pull Request укажите:

- какую задачу решает skill;
- почему он полезен аудитории списка;
- где находится `SKILL.md`;
- как он устанавливается;
- какие признаки качества вы проверили: активность, документацию, releases, тесты или использование сообществом.

## Checklist

Перед отправкой проверьте:

- [ ] Ссылка ведет на исходный репозиторий проекта.
- [ ] Проект относится к Agent Skills.
- [ ] В списке еще нет такого проекта или эквивалентного fork.
- [ ] Описание конкретное и не рекламное.
- [ ] Указана подходящая категория.
- [ ] Есть документация по установке или ручному подключению.
- [ ] Проверены лицензия и основные скрипты установки.
- [ ] Markdown отображается корректно.

## Создание собственного skill

Минимальная структура:

```text
my-skill/
└── SKILL.md
```

Минимальный frontmatter:

```yaml
---
name: my-skill
description: Explains what the skill does and when the agent should use it.
---
```

Рекомендуется также добавить:

- конкретные инструкции и порядок действий;
- положительные и отрицательные примеры активации;
- проверки результата;
- `references/` для больших справочных материалов;
- `scripts/` только для понятной и проверяемой автоматизации;
- тестовые сценарии для типичных и пограничных запросов.
